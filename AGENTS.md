# AGENTS.md

## Project Overview

crawlbot2 is a Rust-based automation bot for [DCSS (Dungeon Crawl Stone Soup)](https://dcsscrawl.online/) via the Webtiles WebSocket client protocol. It connects to a locally running DCSS webtiles server, handles compressed binary protocol messages, maintains a 200×200 dungeon map, and implements a routine-based state machine for semi-automated gameplay (auto-register, auto-login, auto-character-creation).

**Key technologies:**
- Rust (edition 2024)
- Async runtime: `tokio` (full features)
- WebSocket client: `tokio-tungstenite` with `rustls-tls-native-roots`
- Compression: `flate2` (raw deflate decompression)
- Serialization: `serde` + `serde_json`
- REPL: `rustyline-async`

**Architecture:** 3-task async model with `tokio::sync::mpsc` channels:
1. **Input handler** — receives WebSocket frames, decompresses, parses JSON stream, auto-responds to `ping` with `pong`
2. **Output handler** — sends messages to WebSocket with 100ms delay between messages
3. **Routine handler** — state machine (`Idle` → `Init` → `StartGame` / `StartSeededGame`) that automates register, login, play, and character selection

**Source files:**
- `src/main.rs` — entry point, WebSocket setup, channel spawning, REPL loop
- `src/protocol.rs` — `GameMessage`, `Routine`, `RoutineMessage` types; `normalize_messages()` for batched JSON
- `src/commands.rs` — `execute_routine()` state machine, `/start` and `/seeded` REPL commands
- `src/map.rs` — `MapState` (200×200 grid), `update_map()`, `print_map()`
- `src/logger.rs` — dual-output logger (stdout via rustyline `SharedWriter` + timestamped files in `./logs/`)

**Protocol spec:** See `asyncapi.yaml` (AsyncAPI 3.1.0) for the full WebSocket protocol and internal channel architecture. Architecture flowchart in `flow.mmd` (Mermaid).

## Setup Commands

### Rust environment
- Install Rust: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
- Build: `cargo build`
- Build (release): `cargo build --release`
- Run: `cargo run`

### TypeScript test client (optional)
```bash
cd test/client && npm install
```

### Research tools (optional)
```bash
cd test/research && npm install
```

## Development Workflow

- **Run the bot:** `cargo run` — connects to `ws://127.0.0.1:8080/socket` (hardcoded)
- **Run the TS prototype:** `cd test/client && npm start`

### DCSS server setup (required for local testing)
The bot requires a running DCSS webtiles server. Two options:

1. **Podman container (recommended):**
   ```bash
   ./test/container/build.sh
   ./test/container/run.sh
   ```
   Starts server on `http://0.0.0.0:8080`, WebSocket at `ws://127.0.0.1:8080/socket`.

2. **Manual:** Run a DCSS webtiles server from [crawl/crawl](https://github.com/crawl/crawl) (tag `0.33.1`) with `make WEBTILES=y`.

### REPL commands (at runtime)
- `/start` — auto-register, login, play `dcss-web-trunk`, auto-pick species/background
- `/seeded` — same flow but plays `seeded-web-trunk` with seed `-122333`
- Any other line is sent as raw input to the game server

## Testing Instructions

- **No automated test suite** currently exists. No `#[test]` functions, no dev-dependencies in `Cargo.toml`, no CI.
- **TypeScript client test:** `test/client/src/test.ts` reads JSON fixtures from `test/research/` and exercises the `map.ts` module. Run manually with Node.
- **Schema validation:** `test/research/schema.js` uses Zod to validate captured DCSS protocol messages.
- **Fixture data:** `test/research/login/` (14 JSON files, `00-login.json`–`13-map.json`) and `test/research/move/` (2 files) contain captured protocol messages.
- **Lint/check:** `cargo clippy` and `cargo fmt --check` work with defaults; no custom config files exist.

## Additional Notes

- **No environment variables** are used. The WebSocket URL (`ws://127.0.0.1:8080/socket`), credentials (`dirkle`/`aaa`), and game IDs (`dcss-web-trunk`, `seeded-web-trunk`) are all hardcoded in `src/main.rs` and `src/commands.rs`.
- **WebSocket protocol:** Messages are JSON lines, sent as binary frames with raw deflate compression. Each frame includes a sync buffer (`0x00 0x00 0xff 0xff`) before the deflate stream. The `handle_binary_message` function in `src/main.rs` handles decompression and JSON stream parsing.
- **Ping/pong:** The bot auto-responds to server `ping` messages with `{"msg":"pong"}`.
- **Log files:** Written to `./logs/` with timestamps in filename.
